# M2 설계: 미국 개별주 유니버스 + 수집 클라우드 이전

- 날짜: 2026-08-16
- 상태: 초안 — 사용자 승인 대기
- 관련 문서: [`docs/event_alpha_design_review.md`](../../event_alpha_design_review.md) §8.5, §8.6,
  [`docs/superpowers/specs/2026-08-12-event-alpha-design.md`](2026-08-12-event-alpha-design.md) §4
- 선행 완료: M1 — 이벤트 캘린더(KR/US), 오버레이, 승격 측정 경로

## 1. 한 문단 요약

M1로 이벤트가 SEC에서 브로커까지 도달하는 것을 확인했지만, 그 이벤트를 적용할
미국 개별주가 없다. 지금 미국 유니버스는 ETF 11종이고 ETF에는 실적 발표가 없다.
M2는 개별주 유니버스를 만든다. 구성종목 목록을 받아쓰는 대신 **자기 가격
데이터에서 시점별로 재구성**하고, 그렇게 해도 남는 생존자 편향은 해결했다고
주장하지 않고 **크기를 재서 기록한다**. 수집량이 PC로 감당할 규모를 넘으므로
클라우드 이전을 같은 마일스톤에 넣는다.

## 2. 문제

| | 현재 | 필요 |
|---|---|---|
| 미국 유니버스 | ETF 11종 | 개별주 300~500 |
| 실적 이벤트 | **0** (ETF) | 수천 건 |
| 분위 검정 | 분위당 2.2종목 | 분위당 60~100종목 |
| 오버레이 대상 | 없음 | 구조 전략 |

`us_etf_rotation` 판정문이 이미 진단한 것이다: *"11종을 5분위로 나누면 분위당
2.2종목이라 IC IR과 단조성이 통계적으로 불안정하다. 신호가 없어서가 아니라
유니버스가 작아서다."*

## 3. 유니버스 설계

### 3.1 정적 테마로는 담을 수 없다

`data/universe.py`의 `Theme`은 `ThemeMember(symbol, start, end)` 튜플이다.
`config/themes.toml`에 손으로 적고, `from` 없는 멤버는 로더가 거부한다. 5~11종목
규모에서는 이 규율이 잘 작동했다.

500종목에서는 성립하지 않는다. 편입·편출을 손으로 유지할 수 없고, **오늘의
목록을 과거에 소급 적용하는 순간 그 로더가 막으려던 바로 그 편향이 들어온다.**

그래서 유니버스를 **함수**로 만든다.

```text
members(dt) = 그 시점까지의 데이터로 계산한 거래대금 상위 N
```

정적 테마는 그대로 둔다 — 두 방식이 공존하고, 전략은 어느 쪽이 왔는지 몰라도
된다.

### 3.2 PIT 재구성 규칙

각 리밸런싱일 `dt`에:

```text
1. 후보 풀에서 dt 이전 거래일까지의 종가·거래량을 읽는다
2. dollar_volume_20d = mean(close × volume, 최근 20 거래일)
3. 최소 상장기간·최소 가격 필터 적용
4. 상위 N 선정
```

**모든 입력이 `dt` 이전이다.** 미래 정보가 들어갈 자리가 없다. `research.toml`에
이미 `min_avg_value_20d`, `min_listing_days` 개념이 있으므로 그 값을 쓴다.

리밸런싱 사이에는 유니버스를 고정한다. 매일 재계산하면 경계 근처 종목이
들락거리며 회전율만 만든다.

### 3.3 후보 풀 — 그리고 생존자 편향이 실제로 있는 자리

상위 N을 뽑으려면 후보 풀이 있어야 하고, 풀에는 **그 시점에 상장돼 있던 종목이
전부** 들어 있어야 한다. 여기가 어려운 지점이다.

- NASDAQ Trader 디렉터리(`symbols.py`가 이미 쓰는 소스)는 **오늘 상장된** 종목만
  준다. 2015년에 상장돼 있다가 사라진 종목은 없다.
- FinanceDataReader와 Yahoo는 상장폐지 티커의 가격을 제대로 주지 않는다.

즉 "자기 데이터로 재구성"은 **후보 풀이 주어졌을 때** PIT-안전하지, 풀 자체의
편향을 없애지는 못한다. 검토 §8.6이 지적한 그대로다.

### 3.4 그래서 푸는 대신 잰다

편향을 없앴다고 주장하지 않는다. **크기를 재서 리포트에 적는다.**

측정 방법: SEC full-index(`Archives/edgar/full-index/{year}/QTR{q}/form.idx`)는
**그 분기에 실제로 제출된 모든 공시**를 CIK와 함께 나열한다. 상장폐지 여부와
무관하다.

```text
연도별:
  A = 그 해 10-K를 제출한 기업 수        (그때 존재했던 기업)
  B = 그중 우리 후보 풀에 있는 기업 수    (지금도 남아 있는 기업)
  생존율 = B / A
```

이 표를 판정문에 싣는다. 대형주는 생존율이 높고(상폐가 드물며 대부분 M&A),
소형주는 낮을 것으로 예상한다. **생존율이 낮은 구간의 결과는 그만큼 할인해서
읽어야 한다**는 것을 숫자로 말할 수 있게 된다.

세 가지 완화책을 함께 쓴다.

1. **유동성 상위로 제한.** 상위 500위권은 상폐가 드물다
2. **연도별 생존율을 리포트에 명시**
3. **해결됐다고 쓰지 않는다.** 유료 데이터(CRSP, Sharadar)를 사기 전까지는
   남는 한계다

## 4. 클라우드 설계

### 4.1 왜 M2와 함께인가

- **수집량.** 후보 풀 전체(수천 종목) × 11년 일봉 백필은 PC로 몇 시간이다.
  그동안 PC를 못 쓴다
- **시간대.** 미장 정규장이 한국시간 22:30~05:00이다. 마감 후 수집은 새벽이다
- **자격증명.** 미장은 KRX 회원 로그인이 없다. 클라우드 이전의 가장 큰 리스크가
  미장 전환으로 이미 사라졌다
- `.env` 로더가 M1 말미에 들어갔으므로 자격증명 이전도 파일 하나로 끝난다

### 4.2 실제로 걸리는 것

```toml
[tool.uv]
environments = ["sys_platform == 'win32'"]
```

**`uv.lock`이 Windows 전용으로만 풀려 있어 리눅스에서 `uv sync`가 안 된다.**
이 줄을 지우고 lock을 다시 만들어야 한다. 유일한 실질적 코드 장벽이다.

나머지는 이미 괜찮다. `cli.py`는 tkinter를 지연 임포트하므로 헤드리스에서
CLI가 그대로 돌고, `exchange_calendars`가 XNYS 휴장일을 처리하며, 경로는 전부
`PROJECT_ROOT` 상대다.

### 4.3 구성

| 항목 | 선택 |
|---|---|
| 호스트 | 소형 리눅스 VM (미국 리전 — EDGAR·가격 소스와 가까움) |
| 배치 | cron 2개 — 마감 후 수집, 주간 유니버스 재계산 |
| 시간대 | `TZ=America/New_York` (거래소 기준으로 생각하는 게 헷갈림이 적다) |
| 저장 | 영속 디스크에 `data/`, `state/` |
| 자격증명 | `.env` |
| 알림 | 텔레그램 — 수집 결과 요약, 실패 시 즉시 |

**먼저 검증할 것:** FinanceDataReader와 yfinance가 클라우드 IP에서 정상
동작하는지. 이 컨테이너에서 Yahoo가 403으로 막힌 전례가 있다. VM 하나로 30분이면
확인되고, 막히면 유니버스 규모와 가격 소스를 다시 정해야 하므로 **가장 먼저**
한다.

## 6. 단계와 게이트

| 단계 | 내용 | 넘어갈 조건 |
|---|---|---|
| 2a | 클라우드 VM + 데이터 소스 접근성 검증 | FDR·yfinance·EDGAR가 클라우드 IP에서 동작 |
| 2b | 후보 풀 + 가격 백필 | 후보 풀 종목의 2015~ 일봉 확보 |
| 2c | PIT 유니버스 제공자 | 임의 과거 날짜에 상위 N이 재현 가능 |
| 2d | 이벤트 수집 확장 | **이벤트 후보 ≥ 3,000건** |
| 2e | 생존자 편향 측정 | 연도별 생존율 표가 리포트에 기록됨 |

2a가 먼저인 이유: 여기서 막히면 2b 이후의 규모 산정이 전부 달라진다.

## 7. 테스트

| 대상 | 검증 |
|---|---|
| 후보 풀 | ETF·우선주·워런트 제외; 티커 정규화 |
| PIT 상위 N | `dt` 이후 데이터가 결과를 바꾸지 못함 (M1의 look-ahead 테스트와 같은 형태) |
| 유니버스 안정성 | 리밸런싱 사이 고정; 경계 종목이 매일 들락거리지 않음 |
| 정적/동적 공존 | 기존 테마 전략 결과가 한 자릿수까지 불변 |
| 생존율 | 합성 full-index로 A/B 계산 검증 |

**마지막 항목이 회귀 방지선이다.** 유니버스 계층을 건드리면서 기존 KR/ETF
전략 수치가 움직이면 이후 모든 비교가 오염된다.

## 8. 범위 제외

- **서프라이즈·SUE는 M3다.** M2는 유니버스와 가격까지
- 실주문·KIS 연동은 여전히 범위 밖
- 유료 데이터 도입은 하지 않는다. 생존자 편향은 재기만 한다
- 웹 대시보드는 만들지 않는다. 클라우드 관측은 텔레그램 알림까지

## 9. 알려진 한계

- **상장폐지 종목 가격이 없다.** 이것이 이 마일스톤이 해결하지 못하는 문제이고,
  §3.4는 그것을 숨기지 않기 위한 장치다
- 후보 풀이 오늘의 상장 목록이라 과거로 갈수록 편향이 커진다
- 유동성 상위 N은 대형주 편중이다. 소형주 이벤트 알파는 이 유니버스에서 관측되지
  않는다 — 그쪽이 더 클 수도 있다는 점을 기록해 둔다
- 클라우드 비용과 데이터 소스 이용약관은 사용자 확인 사항이다
