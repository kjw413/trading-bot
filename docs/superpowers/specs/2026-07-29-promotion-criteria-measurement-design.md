# 승격 기준 측정 도구 설계

- 날짜: 2026-07-29
- 상태: 사용자 승인 완료 (섹션별 승인)
- 관련 문서: [`docs/theme_multifactor_promotion_review.md`](../../theme_multifactor_promotion_review.md),
  [`docs/us_etf_rotation_review.md`](../../us_etf_rotation_review.md),
  `config/research.toml` `[promotion]`

## 1. 한 문단 요약

"이 전략에 돈을 넣어도 되는가"를 판정하는 규칙이 6개 있는데 그중 3개는 잴
방법이 없다. 그래서 전략을 두 개 만들었지만 어느 쪽도 제대로 된 합격 판정을
받을 수 없었다. 이 작업은 그 3개를 재는 자를 만든다.

## 2. 문제

`config/research.toml`의 `[promotion]` 기준 6개 중 절반이 측정 불가다.

| 기준 | 임계값 | 현재 상태 |
|---|---|---|
| 벤치마크 대비 초과수익 | > 0 | 측정 가능 |
| Sharpe | ≥ 0.5 | 측정 가능 |
| MDD | ≤ 0.25 | 측정 가능 |
| Walk-forward 승률 | ≥ 0.6 | **측정 불가** |
| 연 회전율 | ≤ 6.0 | **측정 불가** |
| 비용 2배 검정 | 초과수익 > 0 | **측정 불가** |

`research/walk_forward.py`는 존재하지만 **팩터의 IC만** 구간별로 계산한다.
전략을 구간별로 돌리는 코드는 없다. 회전율 계산도 `research/quantiles.py`의
팩터 회전율뿐이고 포트폴리오 회전율은 없다. 비용 민감도는 하네스 자체가 없다.

결과적으로 한국 테마 전략과 미국 ETF 로테이션 모두 판정문에 "미검증"으로
남은 항목이 3개씩 있다. 두 전략 모두 초과수익 기준에서 이미 미달이라 결론은
바뀌지 않았지만, **앞으로 어떤 전략이 나와도 합격 판정을 줄 수 없는 상태**다.

## 3. 부수적으로 고칠 것: 미국 초기자본

`initial_cash_us = 10000`(1만 달러)은 ETF 11종 동일비중 기준 종목당 900달러다.
SPY 한 주가 400~600달러라 주식 수 반올림에서 주문의 17~25%가 거부되고, 이
왜곡은 **11종목 벤치마크를 3종목 전략보다 훨씬 심하게** 때린다. 벤치마크가
부당하게 불리했는데도 전략이 졌으므로 기존 "승격 불가" 결론은 뒤집히지
않지만, 격차의 크기는 믿을 수 없는 숫자다.

10만 달러로 올린다. 목적이 전략과 벤치마크의 공정한 비교이므로 실제 투자금과
같을 필요는 없다.

## 4. 접근법: 전용 평가 모듈

새 `research/evaluation.py`가 기존 `run_backtest`와 `calculate_metrics`를
재사용해 세 측정을 수행하고 승격 판정표 하나를 낸다. 팩터 검증
(`research report`)과 전략 검증의 경계를 분리한다 — 두 작업은 입력도 실행
시간도 다르다.

일회성 스크립트는 배제한다. 미국 검증에서 수동 계산에 의존했던 것이 바로 그
방식의 한계였고, 재현도 테스트도 되지 않는다.

## 5. 구조

| 파일 | 책임 |
|---|---|
| `report/metrics.py` (수정) | `annual_turnover(fills, equity_curve, years) -> float` 추가. 회전율은 백테스트 지표라 지표 모듈에 속한다. |
| `research/evaluation.py` (신규) | Walk-forward 구간별 백테스트, 비용 민감도, 승격 판정 조립 |
| `src/tradingbot/cli.py` (수정) | `research evaluate` 서브커맨드 |
| `config/us_etf_rotation.toml`, `us_etf_benchmark.toml` (수정) | `initial_cash_us` 100000 |

`BacktestMetrics`의 기존 필드는 건드리지 않는다 — HTML 리포트와 고정값 회귀
테스트(`tests/test_smoke_backtest.py`)에 영향을 주지 않기 위해서다. 회전율을
리포트에 노출할지는 필요해질 때 별도로 결정한다.

## 6. 세 측정의 계산 방식

### 6.1 Walk-forward — 이름과 실제가 다른 점을 명시한다

`walk_forward_windows(start, end, train_years=3, test_years=1, step_years=1)`로
구간을 만들고, 각 구간의 **검증 기간만** 전략 설정과 벤치마크 설정으로 각각
백테스트해 수익률을 비교한다. 승리 = 그 구간에서 전략 수익률 > 벤치마크
수익률.

**학습 구간은 실제로 사용하지 않는다.** 현재 전략은 파라미터를 데이터로
맞추지 않는 규칙 기반이라 학습할 것이 없다. 따라서 이 측정은 엄밀히는
"롤링 독립구간 일관성 검정"이며, walk-forward라는 이름은 승격 기준의 명칭을
따른 것이다. **리포트에 이 사실을 명시한다.** 나중에 파라미터를 튜닝하기
시작하면 학습 구간이 실제 의미를 갖게 되고, 하네스는 이미 그 모양을 갖추고
있다.

승리 판정을 "수익률 > 0"이 아니라 "벤치마크 초과"로 두는 이유: 승격 1차
기준이 이미 벤치마크 대비 초과수익이고, 장기 상승장에서는 거의 모든 구간이
플러스라 변별력이 없다. 전략이 벤치마크에 지면서도 승률 100%가 나오는 함정을
피한다.

팩터 워밍업은 백테스트 시작일에 영향받지 않는다 — 전략이 엔진 피드가 아니라
자체 `ParquetDataStore`에서 가격을 읽으므로, 구간을 잘라도 모멘텀 계산에
필요한 과거 데이터가 유지된다.

### 6.2 회전율

편도 연 회전율 = 총 매수 체결금액 ÷ 평균 평가자산 ÷ 연수.

- 분자: `Fill.side == BUY`인 체결의 `qty * price` 합계
- 분모: `equity_curve["equity"]`의 평균 (`equity_curve`는 `date`·`equity` 두 컬럼)
- 연수: `(equity_curve["date"].max() - min()).days / 365.25`

평균 평가자산이 0 이하이거나 연수가 0이면 NaN을 반환한다 — 0으로 나눠 무한대를
내거나 0을 반환해 "거래 없음"으로 위장하지 않는다. 승격 기준 6.0(편도 600%)과
직접 대조된다.

### 6.3 비용 민감도

설정을 깊은 복사한 뒤 `[fees.<시장>]`의 모든 수치와 `[execution] slippage_bps`를
배수(기본 2.0)만큼 올려 재실행한다.

**전략과 벤치마크 모두 올린 비용을 문다.** 초과수익은 상대 개념이라 한쪽만
올리면 비교가 성립하지 않는다. 벤치마크도 월간 리밸런싱을 하지만 전략보다 덜
거래하므로, 양쪽을 똑같이 올려도 전략이 더 크게 손해를 본다 — 그것이 의도한
민감도다.

`finra_taf_cap`(상한)도 함께 올린다. 요율만 올리고 상한을 그대로 두면 상한이
비용 증가를 흡수해 검정이 무력해진다.

원본 설정 객체는 변경하지 않는다(복사본 사용).

## 7. 출력

`reports/evaluation/<timestamp>_<strategy>_<market>.md`에 저장한다. 지금까지
판정문은 사람이 한 번 쓰고 마는 `docs/` 문서였지만, 이것은 재실행할 때마다
나오는 산출물이므로 `reports/`가 맞다.

내용:

1. **맨 위에 전문용어 없는 한 문단 결론.** 판정을 보고 결정할 사람이 읽을 수
   없으면 도구가 제 역할을 못 한다. "합격/불합격"과 그 이유를 평이한 말로 쓴다.
2. 승격 기준 6개 전부에 대한 측정값·임계값·통과 여부 표
3. 구간별 Walk-forward 결과 (구간 날짜, 전략 수익률, 벤치마크 수익률, 승패)
4. 1배/2배 비용 비교
5. 재현 명령

`record_experiment`로 실험 기록도 남겨 git 커밋 해시와 함께 추적된다.

## 8. 오류 처리

- 구간 하나의 백테스트가 실패해도 나머지는 계속 돌린다. 실패한 구간은 **승패
  계산에서 제외하되 리포트에 실패로 표시**한다. 조용히 분모에서 빼면 승률이
  부풀려진다.
- 유효 구간이 하나도 없으면 승률은 NaN이고 그 기준은 **"측정 불가"로 남는다 —
  통과로 처리하지 않는다.** 데이터가 부족해 구간이 아예 만들어지지 않는 경우도
  같다.
- 어떤 기준이든 측정에 실패하면 판정은 "합격"이 될 수 없다. 미측정과 통과를
  구분하는 것이 이 도구의 존재 이유다.

## 9. 테스트

모두 네트워크 없이 합성 가격 fixture로 수행한다.

| 대상 | 검증 |
|---|---|
| 회전율 | 알려진 매수 금액·평가자산으로 계산값 검증; 거래 없으면 0 |
| 비용 배수 | 배수가 실제 적용되어 순수익이 낮아지는지; 원본 설정이 변경되지 않는지 |
| Walk-forward | 구간 분할; 실패 구간이 분모에서 빠지되 리포트에 남는지; 유효 구간 0개면 NaN |
| 판정 | 하나라도 미달이면 "승격 불가"; 미측정 항목이 통과로 둔갑하지 않는지 |
| 회귀 | 기존 백테스트·HTML 리포트 결과가 이번 변경으로 달라지지 않음 |

## 10. 범위 제외

- **파라미터 탐색·최적화는 넣지 않는다.** 이 도구는 측정만 하고, 무엇을 바꿀지는
  사람이 결정한다. 측정 도구에 탐색기를 붙이면 과최적화가 자동화된다.
- 회전율을 HTML 리포트에 노출하는 것은 이번 범위가 아니다.
- 새 전략이나 팩터 개선은 이번 범위가 아니다. 자를 먼저 만들고, 그다음에 잰다.
